GUARDRAIL DEMO - INVOICE AND USER-QUERY TEST CASES
================================================
All inputs here are synthetic. No real credentials or customer documents.

START WITH THIS IMPORTANT DISTINCTION
Document scan: injection flag/fence, NOT automatic document rejection.
Query scan: a detected unsafe user query can be BLOCKED immediately.
Business validation: an ERP mismatch can produce a REJECT recommendation.
Risk gate: reject/high-risk -> pending_review, no normal automatic indexing.
These are different outcomes. Do not call all of them a guardrail rejection.

NORMAL / EDGE CASE NOTES
Q10: query guard allows the question. Final answer depends on selected approved
indexed evidence; an empty index is not a prompt-injection failure.
Q11 (weather): current explicit scope regex does NOT block this exact query.
RAG may still return no evidence/low quality, but do not claim this proves an
explicit out_of_scope guardrail block.
Q12 (empty): direct helper/API-style edge case. The Streamlit UI may not submit
an empty box, so it is not necessarily a clickable UI test.

OPTIONAL AUTOMATED CHECKS

The script uses the actual guardrail/risk functions, loads config/rules.yaml,
disables cloud tracing IN THAT TEST PROCESS and writes DIRECT_TEST_RESULTS.json.

Current observed result: 22/22 direct checks passed. Existing saved results are
reference evidence; rerun to verify the version/config used in your own lab.
