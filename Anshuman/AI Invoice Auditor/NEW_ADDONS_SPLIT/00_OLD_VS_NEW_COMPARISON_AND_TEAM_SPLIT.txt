3. OPTIONAL THEN IMPLEMENTED IS NOT THE SAME AS NEVER MENTIONED
---------------------------------------------------------------
Old PDF page 3 explicitly says recommendation 'Need not be implemented!!' and
revalidation 'Need not be implemented!'. Yet its overview/functional text still
mentions recommendations, corrections and revalidation. Classify correctly:

- Full edit -> revalidate -> explicit approve/reject -> indexing loop:
  implemented beyond the waived/optional minimum, not an entirely new concept.
- risk_gate weighted score + conditional indexing: a concrete added policy.
- Watcher pause/resume/stats and system directories: operational enhancements
  to old monitoring, not newly invented invoice monitoring.

The older PPT called human-in-the-loop entirely 'Beyond Scope'. The revised
slides qualify this instead of copying that stronger claim.

4. CURRENT-CODE FACTS THAT CORRECT THE OLD SLIDE NARRATIVE
----------------------------------------------------------
A. Current workflow has eight named nodes:
   extractor -> translator -> parser -> validator -> business_validation
   -> reporter -> risk_gate -> conditional indexing.
   It is not simply a six-stage flow because six containers exist.

B. Revalidation order is validator -> reporter -> compute_risk, then an explicit
   pending_review update. It is not validator -> risk_gate -> reporter.

C. Current persistence upserts invoice data and replaces line rows. Feedback
   is recorded separately, but original structured extraction/report versions
   are not immutable end to end. Do not repeat that claim from the old PPT.

D. Registry source declares 13 tool decorators and 7 agent cards. README's
   'eleven tools' wording is stale. Verify runtime /mcp/tools and /agents.

E. MCP/A2A are custom implementations. Default empty transport URLs use
   in-process dispatch, not a network request per tool/delegation.
   Do not claim official SDK conformance or secure authentication from names alone.

F. ADK executes with a Bedrock LiteLlm model when configured and usable; otherwise
   it falls back to deterministic tool calls. Executor/mode is demo evidence.
   The LLM wrapper is direct LiteLLM Bedrock, not ChatBedrockConverse.

G. Old RAG already had the triad/retry requirement. New named tool boundaries,
   safety and tracing augment that RAG. Current default max_retries=3 is three
   total attempts in its implementation, not four.

H. Langfuse facade can include input/output payloads. Truncation is not universal
   redaction. A synthetic generation test is not full per-call cost/token coverage.

I. ERP HTTP is the normal boundary, but graph validator has a direct ERP helper
   fallback. A current fallback is not a new approved enterprise integration.

J. Old required SQL routing for structured questions and original-value
   preservation should not be silently declared satisfied: current RAG path is
   not a fixed SQL router, and correction upserts alter current structured data.

These caveats are explanation accuracy, not requests to modify the selected code.
No application changes were made for this study split.
