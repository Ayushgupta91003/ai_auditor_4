MINUTE 1-4: guardrails.py - SABSE IMPORTANT FILE
------------------------------------------------
Location: services/agent/utils/guardrails.py
Kaam: selected input/output boundaries par safety controls.

SIRF YE THREE MAIN FUNCTIONS PAKKE KARO:

scan_document():
Invoice text inspect karta hai. Supported secrets strip karta hai; injection
mile toh warning/fence lagata hai. Document audit continue kar sakta hai.
Poora document discard nahi karte, warna attacker audit se bach sakta hai.

scan_user_query():
Auditor ka question check karta hai. "Ignore previous instructions" jaisi
override ya configured out-of-scope query ko block kar sakta hai.

scan_answer():
Generated answer mein supported PII/secrets mask karta hai aur context support
check karta hai. Grounding kam ho toh refusal de sakta hai.

HELPERS KA BAS MEANING:
detect_injection() -> suspicious instructions identify.
detect_out_of_scope() -> configured unrelated/prohibited topics identify.
redact_pii() -> email/phone jaise supported personal details mask.
strip_secrets() -> supported passwords/keys mask.
groundedness() -> answer words kitne context mein supported hain, lexical ratio.
scan_report() -> optional report redaction; current setting disabled hai.
_record() -> findings log/trace karne ki koshish.

Return object GuardrailResult mein text, allowed, findings, blocked_reason hain.
Yeh application regex/lexical controls hain; perfect safety ya AWS managed
Bedrock Guardrails ka claim nahi karna.

MINUTE 4-6: risk_scoring.py - CALCULATION
-----------------------------------------
Location: services/agent/utils/risk_scoring.py
Main function: compute_risk(state, rules).
Input: findings/errors/confidence/recommendation aur configured rules.
Output: score, review_status, reasons.

Default finding weights:
CRITICAL 1.00 | ERROR 0.60 | WARNING 0.30 | INFO 0.10.
Extra data-error/confidence weights aur hard blocks bhi hain.

No hard block + score <= 0.30 -> auto_approved.
Hard block OR score > 0.30 -> pending_review.

Example: one ERROR = 0.60 -> normally human review.
0.60 ka matlab 60% fraud probability NAHI. Weighted rule score hai.
Hard block score low hone par bhi review force kar sakta hai.

compute_risk khud indexing nahi karta, sirf result calculate karta hai.
If asked about an edge case: confidence ka current "value or 1.0" expression
exact 0.0 ko 1.0 treat karta hai; zero-confidence handling perfect nahi hai.

MINUTE 6-7: rules.yaml - SETTINGS
---------------------------------
Location: config/rules.yaml. Yeh utils ke andar nahi hai.
Functions nahi hain; settings hain.

responsible_ai: injection/scope checks, PII/secret switches, grounding floor.
risk_scoring: weights, hard blocks aur auto-approval threshold.

Numbers mix mat karna:
Risk threshold 0.30 -> routing.
Answer grounding floor 0.30 -> lexical support.
RAG triad >0.70 -> separate RAG quality check.

MINUTE 7-8: workflow.py - DECISION KO FLOW SE CONNECT KARNA
-----------------------------------------------------------
Location: services/agent/graph/workflow.py

risk_gate_node():
compute_risk call karta hai, score/status state mein set karta hai, database
review status save karne ki koshish karta hai.

_route_after_gate():
auto_approved -> indexing node.
Otherwise -> graph END; pending case human decision ka wait karega.

Normal flow: Report -> Risk gate -> Index OR Pending review.
Important: current reject endpoint already indexed vectors automatically
delete nahi karta. Normal gate ko universal access control mat bolna.
